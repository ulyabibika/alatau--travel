# «Alatau Travel» туристік агенттігінің ақпараттық жүйесі (ТААЖ)

**Орындаған:** Райымжанова Улья  
**Пән:** Ақпараттық жүйелер негіздері  
**Жоба мақсаты:** Клиенттің турды іздеуінен бастап ваучерді алуына дейінгі тізбекті бір ортаға жинау, бос орын мен бағаны автоматты көру және менеджер уақытын қағаз жұмысынан босату.

## Жүйе пайдаланушылары
- **Клиент (турист):** Турды іздейді, салыстырады, брондайды, төлейді, ваучер алады.
- **Менеджер (турагент):** Күрделі өтінімдерді тексереді, каталогты жаңартады, кеңес береді.
- **Әкімші:** Пайдаланушылар мен рөлдерді басқарады, жүйе журналын бақылайды.
- **Бухгалтер / Директор:** Төлемдерді көреді, сатылым есептерін алады.
- **Сыртқы жүйелер:** Kaspi/Банк төлем шлюзі, Серіктес API (қонақүй мен авиакомпаниялар).

## Жүйе компоненттері
- Пайдаланушы интерфейсі (Web + Mobile)
- Авторизация және аутентификация модулі
- Іздеу модулі
- Брондау (бизнес-процестер) модулі
- Деректерді басқару модулі (PostgreSQL)
- Хабарламалар модулі (SMS/Email)
- Есеп беру модулі
- Әкімшілік басқару модулі

# Талаптарды талдау және қалыптастыру

## 1. Функционалдық талаптар (FR)
- **FR-01:** Жүйе тіркелмеген пайдаланушыға каталогты қарауға рұқсат етуі тиіс, ал брондау тек кіргеннен кейін ашылуы тиіс.
- **FR-02:** Жүйе турларды ел, қала, күн аралығы, түн саны, баға және тамақтану түрі бойынша сүзгілеуі тиіс.
- **FR-03:** Жүйе таңдалған тур бойынша серіктес API-ден бос орынды сұрауы және нәтижені көрсетуі тиіс.
- **FR-04:** Жүйе брон жасағанда кемінде бір жолаушының аты-жөні мен төлқұжат деректерін міндетті етуі тиіс.
- **FR-05:** Жүйе төлем басталған соң бронды 30 минутқа «күтуде» статусында ұстауы, уақыт бітсе орынды босатуы тиіс.
- **FR-06:** Төлем расталған соң жүйе PDF ваучерді қалыптастырып, клиенттің поштасына және жеке кабинетіне салуы тиіс.
- **FR-07:** Менеджер күрделі өтінімді (виза, топ) өз тақтасынан қабылдап, растауы немесе қайтаруы тиіс.
- **FR-08:** Директор мен бухгалтер кезең, менеджер және бағыт бойынша сатылым есебін Excel-ге жүктей алуы тиіс.

## 2. Функционалдық емес талаптар (NFR)
- **NFR-01:** Каталог бетінің жауап беру уақыты 3 секундтан аспауы тиіс.
- **NFR-02:** Жүйе қолжетімділігі айына кемінде 99.5% болуы тиіс.
- **NFR-03:** Құпиясөз хэшпен сақталады, төлқұжат нөмірлері шифрланады.
- **NFR-04:** Интерфейс қазақ және орыс тілдерінде жұмыс істеуі тиіс.
- **NFR-05:** Негізгі сценарийлер (іздеу–брон–төлем) 10 минуттық нұсқаусыз орындалуы тиіс.
- **NFR-06:** Сақтық көшірме тәулігіне бір рет жасалады, соңғы 14 күн сақталады.

# Use Case Сценарийлері

## UC-01. Жүйеге кіру / тіркелу
- **Actor:** Клиент, Менеджер, Әкімші
- **Сценарий:** Телефон/email және құпиясөзді енгізу, жүйе тексеріп, тиісті басты бетті ашу.

## UC-03. Турды брондау
- **Actor:** Клиент
- **Бастапқы шарт:** Клиент жүйеге кірген, тур карточкасы ашық, бос орын бар.
- **Негізгі сценарий:**
  1. Клиент «Брондау» батырмасын басады.
  2. Жолаушылардың аты-жөнін, туған күнін, төлқұжат нөмірін енгізеді.
  3. Жүйе бос орынды тексеріп, бронды «күтуде» статусымен 30 минутқа сақтайды.
  4. Төлем бетіне бағыттайды (UC-04).
  5. Төлем расталса, статус «төленді» болады, PDF ваучер жасалады.

## UC-05. Өтінімді өңдеу
- **Actor:** Менеджер
- **Сценарий:** Менеджер «қолмен тексеру» статусындағы өтінімді ашып, растау немесе себебін жазып қайтару таңдайды.
EOT
